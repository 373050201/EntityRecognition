# 公平双模型流水线

该目录实现两个完全独立的RT-DETRv2模型：图元模型负责图元框、类别和锁状态，文字模型负责文字框和编号。两个模型不共享特征，也不把图元检测结果输入文字模型；最终只通过基于几何距离的匈牙利一对一匹配组装完整实体。

## 使用顺序

1. 在`config.yaml`中确认数据、设备和训练参数。
2. 运行`train_symbol.py`训练图元模型。
3. 运行`train_text.py`训练文字检测识别模型。
4. 运行`tune_pipeline.py`，仅在验证集上搜索并写入最佳流水线参数。
5. 运行`evaluate_pipeline.py`，在测试集上评估一次完整流水线。

所有训练检查点默认直接保存在本目录：

- `symbol_best.pt`、`symbol_last.pt`
- `text_best.pt`、`text_last.pt`

匹配距离门限只能使用验证集调整，确定后再运行测试集评估。

## 文件说明

- `config.yaml`：两个模型、训练、匹配、测试和检查点路径的统一配置。
- `dataset.py`：读取原始实体JSON，并同时生成图元模型和文字模型所需标注。
- `models.py`：定义独立图元RT-DETRv2、独立文字RT-DETRv2和CTC识别头。
- `losses.py`：定义图元检测与锁状态损失、文字检测与CTC损失。
- `utils.py`：坐标转换、CTC编解码、复现控制及各层级F1评估。
- `matcher.py`：计算图元中心到文字框的几何距离，并执行匈牙利一对一匹配。
- `train_symbol.py`：训练图元模型，以图元框、类别和锁状态联合F1选择最佳模型。
- `train_text.py`：独立训练文字模型，以文字框和识别内容均正确的文字完整F1选择最佳模型。
- `tune_pipeline.py`：缓存两个模型的验证集输出，以实体F1搜索置信度和匈牙利匹配距离门限。
- `evaluate_pipeline.py`：在测试集上评估完整实体指标、两模型损失和端到端效率。
